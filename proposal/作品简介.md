# 作品简介

## 项目名称

软件测试多 Agent 协作团队——以并行执行换效率、以独立推理去偏见的「审查 → 根因定位 → 修复验证 → 复盘沉淀」缺陷处理闭环。

## 问题与场景

面向软件测试与缺陷管理流程（QA / DevOps团队），解决三类真实痛点：缺陷多源重复上报去重难、根因定位依赖资深工程师且易被第一假设锚定、修复"爆炸半径"难评估且回归风险高。

## 核心解决方案

三个 Team 串联闭环：审查 Team 多判据并行判重并按证据质量裁决，调查 Team 多假设独立取证、主动证伪后按证据链收敛根因，修复 Team实施最小修复并经隔离评审与并行测试验证，全程以结构化 JSON 契约交接、Schema 校验作为流程门禁，修复无效则回退重审而非重复修复。

## 创新点和差异化优势

不靠"更多 Agent"堆量，而是把去偏见机制工程化：视角在任务分配阶段强制分化、Worker间信息隔离、评审者不见修复推理、证据不足结论一律淘汰（禁止多数投票），并通过对照实验（多 vs 单Agent、隔离开关、证据门禁开关）量化证明每项设计的增量价值。

## 开发和复用价值

角色（ROLE.md）、技能（Skill playbook）、交接契约（SOP Schema）三层分离、可独立复用与回灌，评估采用 SWE-bench 风格以测试用例判定修复成败而非 Agent 自报，为同类多 Agent 工程落地提供了可复算、可复现的度量范式。
